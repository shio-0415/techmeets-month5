# 練習課題2：ブログシステムのDB設計書

## テーブル定義

### users（ユーザー）

| 項目名 | 説明 |
|---|---|
| user_id | 自動で振られる番号（主キー） |
| email | メールアドレス |
| password_hash | ハッシュ化されたパスワード |
| name | 表示名（投稿者名） |

### posts（記事）

| 項目名 | 説明 |
|---|---|
| post_id | 自動で振られる番号（主キー） |
| user_id | この記事を書いた人（usersと紐づく） |
| title | 記事のタイトル |
| content | 記事の内容 |
| created_at | 投稿日時 |

### comments（コメント）

| 項目名 | 説明 |
|---|---|
| comment_id | 自動で振られる番号（主キー） |
| user_id | 誰がコメントしたか（usersと紐づく） |
| post_id | どの記事へのコメントか（postsと紐づく） |
| content | コメントの文章 |
| created_at | コメント日時 |

### tags（タグ）

| 項目名 | 説明 |
|---|---|
| tag_id | 自動で振られる番号（主キー） |
| name | タグ名（「旅行」「グルメ」など） |

### post_tags（記事とタグの組み合わせ・中間テーブル）

| 項目名 | 説明 |
|---|---|
| post_id | 記事のID（postsと紐づく） |
| tag_id | タグのID（tagsと紐づく） |

## ER図（テーブル同士の関係）

- users（1）─（多）posts：1人のユーザーは複数の記事を書ける
- users（1）─（多）comments：1人のユーザーは複数のコメントを書ける
- posts（1）─（多）comments：1つの記事は複数のコメントを持てる
- posts（多）─（多）tags：1つの記事は複数のタグを持てて、1つのタグも複数の記事に使われる（`post_tags`を介して実現）

\`\`\`
users ──1───多── posts ──1───多── comments
  │                  │
  └──────1───多───────┘
                       posts ──多───多── tags
                        （post_tagsを介して実現）
\`\`\`
