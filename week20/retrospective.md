# 振り返りレポート（Keep / Problem / Try）

## Keep（良かったこと）

自分で考えて、要件・設計・優先順位をすべて自分の言葉で組み立てられたこと。Week18の要件定義からWeek20のスプリント計画まで、誰かに言われた通りに作るのではなく、自分の実体験（締め切りが重なって困った経験など）を出発点にして、コンセプト・機能・優先順位を一貫して考え抜けた。

## Problem（問題点）

最初に見積もった工数（22日）が、実際に使える期間（平日15日）と大きくズレていた。また、API仕様書に「タスクの編集・削除」のエンドポイントを用意していたにもかかわらず、工数見積もり表にはその作業が最初から入っておらず、後から指摘されて気づいた。

## Try（改善策）

工数見積もりを作成した後、API仕様書に書いたエンドポイントの数と、見積もり表の項目数を突き合わせて確認する。これにより、「仕様には書いたのに見積もりに入れ忘れる」といった抜け漏れを、早い段階で見つけられるようにする。
